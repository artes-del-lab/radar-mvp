# РАДАР — MVP

Система раннего обнаружения тендеров на спецтехнику (Caterpillar, Komatsu,
Hitachi, John Deere). Полный цикл прототипа:

**найденный тендер → оценка релевантности (Claude) → черновик первого сообщения ЛПР**

Система ничего не отправляет сама — только готовит черновик для менеджера.
Бриф: [`docs/radar-project-brief.md`](docs/radar-project-brief.md).

## Статус

| Шаг | Что | Статус |
|---|---|---|
| 1 | Структура проекта | ✅ |
| 2 | Тестовый датасет (15 тендеров) | ✅ |
| 3 | Клиент Tenderplan API + мок-режим | ⏳ |
| 4 | Оценка релевантности через Claude | ⏳ |
| 5 | Генерация черновика касания | ⏳ |
| 6 | Дашборд | ⏳ |
| 7 | Полная инструкция запуска | ⏳ |

## Структура

```
radar-mvp/
├── backend/                 # Python + FastAPI: логика и API для дашборда
│   ├── app/
│   │   ├── config.py        # чтение ключей из .env, выбор mock/реальных данных
│   │   ├── criteria.py      # критерии отбора: коды ОКПД2 (28.92, 29.10 без легковых)
│   │   └── models.py        # единый формат тендера внутри системы
│   └── requirements.txt     # зависимости Python
├── frontend/                # дашборд (HTML/JS, без сборки)
├── data/
│   ├── mock_tenders.json    # тестовые тендеры
│   └── README.md            # какие ответы ожидаем по каждому тендеру
├── docs/
│   └── radar-project-brief.md
├── .env.example             # шаблон для ключей API
└── README.md
```

## Ключи API

```bash
cp .env.example .env
```

В `.env` впишите:

- `ANTHROPIC_API_KEY` — нужен для оценки и черновиков;
- `TENDERPLAN_API_KEY` — пока можно оставить пустым: без него система берёт
  тендеры из `data/mock_tenders.json`.

Команды запуска появятся на шаге 7, когда будут готовы бэкенд и дашборд.
