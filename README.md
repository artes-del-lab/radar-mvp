# РАДАР — MVP

Система раннего обнаружения тендеров на спецтехнику (Caterpillar, Komatsu,
Hitachi, John Deere). Полный цикл прототипа:

**найденный тендер → оценка релевантности (Claude) → черновик первого сообщения ЛПР**

Система ничего не отправляет сама — только готовит черновик для менеджера.
Бриф: [`docs/radar-project-brief.md`](docs/radar-project-brief.md).

---

## Быстрый старт

Нужен **Python 3.10 или новее**. Проверить: `python3 --version`
(на Windows — `python --version`). Если Python нет — скачайте с
https://www.python.org/downloads/ (на Windows при установке отметьте
«Add Python to PATH»).

### 1. Скачать проект

```bash
git clone https://github.com/artes-del-lab/radar-mvp.git
cd radar-mvp
git checkout claude/radar-tender-mvp-jh8u0b
```

### 2. Установить зависимости

macOS / Linux:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows (PowerShell):

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`.venv` — «виртуальное окружение»: отдельная папка с библиотеками проекта,
чтобы они не смешивались с остальной системой. Команду `activate` нужно
повторять в каждом новом окне терминала перед запуском.

### 3. Вписать ключи

Из корня проекта (папка `radar-mvp`):

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

Откройте `.env` в любом текстовом редакторе и заполните:

| Переменная | Что это | Где взять |
|---|---|---|
| `ANTHROPIC_API_KEY` | Ключ Claude — для оценки и черновиков | https://console.anthropic.com → API Keys (нужно пополнить баланс) |
| `TENDERPLAN_API_KEY` | Ключ Тендерплана — для реальных тендеров | Личный кабинет Тендерплана → API. Пусто — тестовые данные |
| `TENDERPLAN_SEARCH_KEY_ID` | ID сохранённого поиска в Тендерплане | Необязательно. Пусто — все ваши поиски |
| `DATA_SOURCE` | `auto` или `mock` | `mock` — всегда тестовые данные, даже если ключ Тендерплана задан |
| `ANTHROPIC_MODEL` | Модель Claude | `claude-opus-5` (по умолчанию, точнее) или `claude-sonnet-5` (дешевле) |

Файл `.env` в git не попадает — ключи остаются только на вашем компьютере.

**Доступ к Claude через сторонний шлюз** (если ключ куплен не напрямую у Anthropic,
а у посредника): оставьте `ANTHROPIC_API_KEY` пустым и впишите

```
ANTHROPIC_BASE_URL=https://адрес-шлюза
ANTHROPIC_AUTH_TOKEN=токен-шлюза
ANTHROPIC_MODEL=claude-opus-5
```

Резервная модель при отказе (`ANTHROPIC_FALLBACKS`) для шлюза по умолчанию
выключена — посредники обычно не поддерживают эту бета-функцию. Учтите: шлюз
видит всё, что уходит в Claude (тексты тендеров и черновики писем). Для тестовых
данных это неважно, для реальной переписки с клиентами лучше прямой ключ Anthropic.

### 4. Запустить

Из папки `backend` с активированным окружением:

```bash
uvicorn app.main:app --reload
```

Откройте в браузере **http://localhost:8000**. Остановить сервер — `Ctrl+C`.

Без ключа Anthropic дашборд тоже открывается: видны тендеры и отсев
предфильтром, а оценка и черновики покажут подсказку про ключ.

---

## Как пользоваться дашбордом

1. **«Оценить все»** (вверху справа) — Claude оценит все тендеры, которые ещё не
   оценены. Это единственное место, где тратятся деньги; результаты сохраняются,
   и при следующем открытии страница показывает их мгновенно.
2. Кликните тендер слева — справа откроется карточка: данные лота, балл,
   обоснование и разбор по четырём критериям (предмет, бренд, цена, срок).
3. **«Сгенерировать черновик касания»** — письмо контактному лицу заказчика.
   Текст можно править прямо в окне, затем «Скопировать письмо».
   Поля в [квадратных скобках] заполните сами. **Письмо никуда не отправляется.**
4. «Переоценить» и «Другой вариант» — новая оценка / новая версия письма.

### Подготовка к демо

1. В `.env`: ключ Anthropic, `DATA_SOURCE=mock` (или `auto` с ключом Тендерплана).
2. Запустите сервер и заранее нажмите «Оценить все» — на созвоне ничего не будет
   грузиться.
3. Заранее сгенерируйте черновики для 2–3 сильных примеров. На тестовых данных
   это TND-001 (экскаватор Caterpillar 320), TND-002 (бульдозеры Komatsu),
   TND-005 (карьерный экскаватор Hitachi за 245 млн).
4. Для контраста покажите отсеянные: мебель и Lada Vesta (отсеяны без Claude),
   бульдозер CAT D6 с истёкшим сроком, автокран на шасси КАМАЗ.
5. Ожидаемые оценки по каждому тестовому тендеру — в [`data/README.md`](data/README.md).

## Реальные данные Тендерплана

1. В личном кабинете Тендерплана создайте **ключ поиска** — сохранённый запрос:
   слова «экскаватор», «бульдозер», «погрузчик», «кран», «грейдер», «трактор»,
   бренды и коды ОКПД2 28.92, 28.30, 29.10.
2. Выпустите API-токен и впишите в `TENDERPLAN_API_KEY`, `DATA_SOURCE=auto`.
3. Если поисков несколько — впишите ID нужного в `TENDERPLAN_SEARCH_KEY_ID`.
4. Перезапустите сервер. В шапке дашборда будет «Источник: Тендерплан».

Вернуться к тестовым данным — `DATA_SOURCE=mock` и перезапуск.

Разбор ответа Тендерплана написан по примерам из их документации
(https://tenderplan.ru/api/doc/) и ещё не проверен на реальном ключе. На первом
запуске проверьте: коды ОКПД2, тип закупки (44-ФЗ/223-ФЗ), ссылку на карточку
тендера и названия регионов — см. пометки в `backend/app/tenderplan_client.py`.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `python3: command not found` / `python не является командой` | Установите Python 3.10+, на Windows — с галочкой «Add to PATH» |
| `uvicorn: command not found` | Не активировано окружение: `source .venv/bin/activate` (Windows: `.venv\Scripts\Activate.ps1`) |
| PowerShell: «выполнение сценариев отключено» | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, затем снова `activate` |
| `Address already in use` | Сервер уже запущен в другом окне, или порт занят: `uvicorn app.main:app --port 8001` |
| Жёлтая плашка «Ключ Anthropic не задан» | Впишите ключ в `.env` в корне проекта (не в `backend/`) и перезапустите сервер |
| «Anthropic: ключ или токен не приняты (401)» | Ключ/токен скопирован не полностью или отозван; для шлюза проверьте `ANTHROPIC_BASE_URL` |
| Через шлюз: «ошибка 400» про `fallbacks` или `beta` | Впишите `ANTHROPIC_FALLBACKS=off` |
| Через шлюз: «ошибка 400» про `output_config` | Шлюз не поддерживает структурированные ответы — напишите мне, переделаю на совместимый вариант |
| «Anthropic: ошибка 400 … credit balance» | Пополните баланс в console.anthropic.com → Billing |
| «Тендерплан: ключ API недействителен (401)» | Проверьте `TENDERPLAN_API_KEY`; временно можно `DATA_SOURCE=mock` |
| Оценки «не обновляются» после правки критериев | Кэш: нажмите «Переоценить» или удалите папку `data/cache/` |

## Сколько это стоит

Claude оплачивается за объём текста. Оценка одного тендера — порядка нескольких
центов на `claude-opus-5`, черновик письма — примерно столько же; на
`claude-sonnet-5` примерно вдвое дешевле. Всё кэшируется в `data/cache/`:
повторный показ страницы бесплатен, оценки пересчитываются раз в сутки
(меняется «осталось N дней»), черновики — только по кнопке «Другой вариант».

## Как это устроено

```
radar-mvp/
├── backend/                      Python + FastAPI
│   ├── app/
│   │   ├── main.py               веб-сервер: API + раздача дашборда
│   │   ├── config.py             чтение .env, выбор источника данных
│   │   ├── models.py             единый формат тендера внутри системы
│   │   ├── tenderplan_client.py  получение тендеров: Тендерплан или тестовые
│   │   ├── criteria.py           критерии отбора — правятся без знания кода
│   │   ├── scoring.py            оценка: бесплатный предфильтр + Claude
│   │   ├── outreach.py           черновик первого письма (без отправки)
│   │   └── llm.py                общий вызов Claude и кэш
│   └── requirements.txt
├── frontend/                     дашборд: index.html, styles.css, app.js (без сборки)
├── data/
│   ├── mock_tenders.json         15 тестовых тендеров
│   ├── README.md                 ожидаемая оценка по каждому
│   └── cache/                    сохранённые оценки и черновики (создаётся сама)
├── docs/radar-project-brief.md   бриф
└── .env.example                  шаблон для ключей
```

**Путь тендера:**

1. `tenderplan_client` берёт тендеры из Тендерплана или из `mock_tenders.json` и
   приводит к единому формату — остальная система не знает, откуда они.
2. `scoring` сначала бесплатно отсеивает очевидно чужое (код ОКПД2 вне целевых
   групп и нет ни техники, ни брендов в тексте), остальное отдаёт Claude.
   Claude возвращает балл 0–100, обоснование и статус по четырём критериям.
3. `outreach` по кнопке пишет черновик письма. Неизвестные факты о компании
   (сроки, цены, сервис) остаются в [скобках]; письмо учитывает правила
   44-ФЗ/223-ФЗ — без просьб о преференциях.

**Критерии отбора** — в `backend/app/criteria.py`: коды ОКПД2 (28.92, 28.30,
29.10 без легковых и автобусов), порог НМЦК (1 млн ₽ — ориентир), бренды, типы
техники, регионы. После правки перезапустите сервер и нажмите «Переоценить».

### Консольные команды (без дашборда)

```bash
cd backend
python -m app.scoring              # оценить все тендеры
python -m app.scoring --force      # переоценить заново
python -m app.outreach TND-001     # черновик письма (--force — новый вариант)
```

API с описанием всех методов: http://localhost:8000/api/docs

## Ограничения MVP

- Один источник данных — Тендерплан (или тестовый набор), не весь рынок.
- Письма не отправляются автоматически — только черновик для менеджера.
- Оценка не обучена на архиве сделок компании — работает по заданным критериям.
- Хранение — файлы JSON, без базы данных и без разграничения пользователей.
